# 設計判断と落とし穴の記録

同じ検討を繰り返さないための記録です。要件の原文は [requirements.md](requirements.md) を参照。

## 技術選定

### ビルド工程を持たない

ページ数が少なく（本番 2 枚）、サーバー機能も不要なため、素の HTML / CSS / JS にしました。
`src/index.html` をダブルクリックするだけで動きます。

### Three.js は UMD 版 (r149) を同梱

`file://` で開く要件があるため、`type="module"` + `import` は使えません
（ローカルファイルの ES module は origin `null` で CORS ブロックされる）。
Three.js は r150 以降 UMD ビルドを廃止しているので、**UMD 最終版の r149** を
`src/vendor/three.min.js` に置いています。CDN 参照にしないのはオフラインでも動かすためです。

### 球体テクスチャは画像を使わず JavaScript で生成

Chrome は `file://` のページから読んだ画像を「別オリジン」扱いにするため、
**WebGL テクスチャに転送できません**。`src/js/texture-lab.js` が Canvas 2D で
描いたものを `CanvasTexture` にしています。追加のダウンロードも発生しません。

現在は「カテゴリ色の 4 分割グロー」を採用（`demo/texture.html` の案 2）。
別案に変えたい場合は `src/js/stars.js` の `HIDDTexture.materials.quad()` を
`dots` / `circuit` / `rim` / `nebula` / `globe` に差し替えます。

### カテゴリ名は 3D テキストではなく HTML 要素

球面にテキストを貼ると日本語が歪む・重い・にじむため、球面上のアンカーを
毎フレーム `Vector3.project(camera)` で 2D 座標に変換し、通常の HTML 要素を動かしています。
クリック・ホバー・フォーカスが標準機能で済み、支援技術からも読めます。

## 低スペック PC への配慮

- **静止したら描画ループを止める。** 回転中・アニメーション中だけ `requestAnimationFrame` を回す
- タブが見えていないあいだは描画しない
- 解像度は `devicePixelRatio` 1.5 までに制限
- ライトオブジェクトもポストプロセスも使わず、陰影とリムライトは 1 パスの軽いシェーダで処理
- テクスチャは起動時に 1 枚（512×256）生成するだけ

## 踏んだ落とし穴

### requestAnimationFrame はタブが非表示だと完全に止まる

**重要な処理を rAF の完了に紐づけてはいけません。** 実際に 2 回踏みました。

1. カテゴリをクリック → 回転アニメ完了 → ページ遷移、としていたら、背景タブでは永久に遷移しなかった
2. 星をクリック → 回転アニメ完了 → カードを開く、で同じことが起きた

どちらも **`setTimeout` に切り離して**解決しています。アニメーションは見た目だけの責務にします。

### scroll イベントも描画フレームに紐づいている（3 回目）

フィルムストリップの送りボタンで同じ穴を踏みかけました。
`scrollBy({ behavior: 'smooth' })` はタブが非表示だと**まったく進まず**、
`scroll` イベントも飛んできません。ボタンの有効・無効を `scroll` イベントだけで
更新していたため、「←」が無効のまま押せなくなる状態でした。

`src/js/category.js` の `scrollBySteps()` は、スクロールを出したあと
`setTimeout(updateNav, 60)` と `setTimeout(updateNav, 500)` でも状態を直しています。
`scroll` イベントの購読は指やトラックパッドでの操作用に残してあります。

同じ判断基準です: **フレームが来ないと止まるものに、進行を任せない。**

### デモから本番へ移すときに同じ穴を持ち込んだ（4 回目）

`demo/js/stars.js` から `src/js/stars.js`（本番）へ移すときに、
カードを開く class を `requestAnimationFrame` の中で足すコードをそのまま持ち込んでいました。
**再生は始まっているのに、カードが `opacity: 0` のまま見えない**状態になります。
`setTimeout(..., 20)` に変え、`structure.test.js` で検出するようにしました。

### JS が毎フレーム書く CSS プロパティに transition を掛けない

`.label--brand` に `transition: opacity .8s` が残っていたため、JS が毎フレーム書く
opacity に追従できず、**HIDD の文字が薄いまま止まって見えました**。
JS で制御する値には transition を掛けないこと。

### ノイズのハッシュは論理シフト（`>>>`）を使う

算術シフト（`>>`）だと負の座標で符号ビットが伝播し、XOR 後の最上位ビットが常に 0 になって
**値域が 0〜0.5 に潰れます**（平均 0.25）。星雲・地球儀テクスチャの模様が出なかった原因です。

### ジオデシック球のワイヤーは球面より外側に置く

多面体の辺は弦なので、球と同じ半径だと辺の中間が内側に沈んで隠れます。
detail 2 で約 1.5% のたわみがあるため、半径 1.03 程度に置く必要があります。
（現在は本番からワイヤーを削除済み）

### Points のマーカーは輪郭に隠れる

カメラ距離 3.6 では半径 1.04 以上でないと球の輪郭より外に出ません。
`THREE.Points` は既定で四角く描かれるので、丸くするには放射グラデーションのスプライトが要ります。

### Python の `http.server` は Range 非対応

206 ではなく 200 を返すため、**動画のシークと再生位置の復元が効きません**。
Range に対応した `serve.py` を用意しました。

### Google ドライブの埋め込みは JS から操作できない

別オリジンの iframe なので、再生位置の取得・設定、再生の開始、終了の検知が
**すべて不可能**です（ブラウザのセキュリティ仕様で、ドライブ固有の制限ではありません）。
放置時の自動再生を実現するには、動画をローカルに置くか YouTube 限定公開に移す必要があります。

（ビルド工程を持たない方針と揃えるため）。

## 無人展示で音を出す

### 1 回の操作で解除、以降は無人でも音つき（2026-09-09）

`demo/js/stars.js` に追加し、本番採用にともなって `src/js/stars.js` にもそのまま
持ち込みました。ブラウザは音ありの自動再生を、その場での操作なしには許可しません。
ただし一度でもクリック・タップ・キー操作があれば、そのタブでは**以降ずっと
解除されたまま**になります（`navigator.userActivation.hasBeenActive`）。

これを利用し、`document` に 1 回限りのリスナーを追加しました
（`unlockSound()`、`pointerdown` / `keydown` を各 `{ once: true }` で購読）。
展示を始めるときに画面へ 1 回触れれば、それ以降は無人でも音つきで流れ続けます。
デモには音の設定パネル（`音: あり`）もあり、そこを直接押しても解除されます
（本番の `index.html` に設定パネルはありません）。

**それでも再生がブロックされた場合の保険**
`openCard()` で `v.play()` が rejected したら、まずミュートで再試行するようにしました
（`src/js/category.js` ではなく `src/js/stars.js` / `demo/js/stars.js` 側）。
無人展示で「音ありのまま一切再生できず、12 秒ごとに全部スキップされ続ける」
という壊れ方を避けるためです。

**それでも「PC の電源が入ったら誰も触らず即座に音」が要る場合**
JS だけでは解決できません（ブラウザの仕様のため）。`docs/operations.md` に
`--autoplay-policy=no-user-gesture-required` での Chrome 起動方法を記載しました。
展示専用の Chrome プロファイルを分けることを推奨しています。

### 慣性とズームを本番へ取り込み（2026-09-10）

`demo/inertia.html` / `demo/zoom.html` での比較を経て、本番に反映しました。

| 項目 | 値 | 場所 |
|---|---|---|
| 手を離したあとの減衰 | 0.84（半減期およそ 4 秒） | `FRICTION` |
| ズームの範囲 | 1.75 〜 7.0（既定 3.6） | `CAM_MIN` / `CAM_MAX` / `CAM_DEFAULT` |

操作はホイール・ピンチ（2 本指）・`+` / `-` キー。
Ctrl 併用のホイールはブラウザのページ拡大なので横取りしていません。

**取り込みにあたって直したこと**

1. **星を球面ちょうど（半径 1.0）へ。** 1.04 / 1.05 と浮かせていたため、
   寄ると星だけが輪郭の外へ離れていきました（100% で 27px）。
2. **描画領域を画面いっぱいに。** 小さな枠のままだと寄ったときに球が四角く切れ、
   さらに星と星座線だけが枠の外へはみ出します。
   キャンバス・星・星座線を同じ枠に揃え、ラップで切って境界を 1 つにしました。
3. **スナップと巡回の開始時に速度を消す。** これは減衰を弱めたことで表面化した問題です。
   巡回・スナップの最中は惰性を進めないため速度が凍結され、
   終わった瞬間に古い勢いで回り出していました
   （減衰 0.06 のときは一瞬で消えるので気づけませんでした）。
4. **巡回に戻るときに倍率を既定へ戻す。** 無人展示で、来場者が寄せたまま
   立ち去るとその後ずっと寄ったままになるためです。

`.brand`（球体正面のラベル）を「高度ICTデザイン学科 / 研究成果動画」の 2 行にしました。

## 球体のズーム（採用済み）

`demo/zoom.html`。ホイール（デスクトップ）・ピンチ（タッチ）・+/- ボタンで
カメラを球の中心へ寄せたり引いたりできます。範囲は `CAM_MIN=1.75` 〜 `CAM_MAX=7.0`
（既定 `3.6` は本番と同じ）。

星の見え隠れは `depth = world.z / radius`（ワールド座標の前後方向）で決めていて、
カメラ距離には依存しません。**そのためズームを足しても、既存の見え方の計算式は
一切変えていません。** カメラの `position.z` を動かすだけで済みました。

Ctrl キーを押しながらのホイールはブラウザ本体のページ拡大操作なので、
`e.ctrlKey` のときは何もせず素通りさせています。

### 寄ると球が四角く切れる問題（修正済み）

最初の実装は `stars.css` の既定値をそのまま使っていました。
ラップ 560px 角に 8% の内側余白（＝キャンバス 400px 角）です。
これだと**ズーム 83% あたりで球がキャンバスをはみ出し、四角く切り取られます**。

さらに悪いことに、星と星座線はキャンバスの外側にある別要素なので切られません。
球の四角い断面をまたいで、ページのヘッダーや操作パネルの上まで線が伸びていました。

幾何としては避けられません。垂直画角が 45 度に固定なので、
球の見かけの半径が画角を超えるのは `camZ < 1/sin(22.5°) ≒ 2.61` から、
つまり必ずどこかで切れます。**問題は「切れること」ではなく
「小さな四角い窓の中で切れること」**でした。

そこで `demo/css/zoom.css` で、このデモに限り

1. 描画領域をページの横幅いっぱい・縦にも広く取り直す（同じ倍率でも球が大きく見える）
2. キャンバス・星・星座線を同じ枠（`inset: 0`）に揃える
3. ラップを `overflow: hidden` で切り、3 つとも同じ境界で切れるようにする

としました。寄り切ると「画面いっぱいに球が来ている」見え方になります。

既定倍率での星の吹き出しは、枠まで 61px 以上の余裕があることを実測で確認済みです
（`overflow: hidden` で切れない）。

### 寄ると星が球から浮く問題（修正済み）

星の配置半径が `STAR_R = 1.04` / `MAJOR_R = 1.05` と、球面（半径 1.0）より
4〜5% 浮かせてありました。ズーム 100% では**星が輪郭より 27px 外側**に出て、
球から離れて浮いて見えます。

これは旧 `sphere.js` の名残です。当時マーカーは 3D の `THREE.Points` で、
球に隠れないよう輪郭の外へ押し出す必要がありました（この文書の
「Points のマーカーは輪郭に隠れる」を参照）。
**今の星はキャンバスの上に重ねた HTML 要素なので、そもそも球に隠れません。**
浮かせる理由がないまま値だけが残っていた、というのが実際のところです。

`demo/js/zoom.js` では `STAR_R = MAJOR_R = 1.0`（球面ちょうど）にしました。
はみ出しは 27px → 0px になっています。
**本番にも同じ修正を入れてあります**（上の「慣性とズームを本番へ取り込み」を参照）。

## 球体の慣性（採用済み）

`demo/inertia.html`。本番の減衰は `velYaw *= Math.pow(0.06, dt)` で、
半減期が約 0.25 秒しかありません（1 秒後には元の速度の 6% まで落ちる）。
「勢いが残っている」と感じる間もなく止まるため、減衰の強さ（`Math.pow` の底）を
3 段階の切り替えパネルで比較できるようにしました。

| プリセット | 底の値 | 半減期の目安 |
|---|---|---|
| 現在と同じ | 0.06 | 約 0.25 秒 |
| ふつう | 0.68 | 約 1.8 秒 |
| 重い（弾み車） | 0.84 | 約 4 秒 |

**既定は一番強い「重い（弾み車）」（0.84）にしています**（2026-09-10 に依頼者が選択）。
数式の形自体は本番と同じ指数減衰で、底の値だけを変えています。
回転中は角速度（deg/s）を画面右上に出していて、
実際に「ふつう」プリセットでフリックしたところ 324°/秒 → 299°/秒、
「現在と同じ」プリセットでは 226°/秒 → 168°/秒（同じ経過フレーム数）と、
減衰の速さの違いを数値でも確認しています。

- `src/js/data.js` — 動画は `file`（ローカルパス）のみで指定する。`videoUrl` は削除
- `src/category.html` / `src/js/category.js` — モーダルの `<iframe>` を `<video>` に置き換え
- `src/js/stars.js` — ドライブ埋め込みの再生分岐（`playDrive` / `DRIVE_MS`）を削除。
  `file` 未配置のカードは既存の stall 監視（12 秒）でそのまま次へ送る

**理由**: ドライブ埋め込みは別オリジンの iframe で JS から一切操作できず
（下の「Google ドライブの埋め込みは JS から操作できない」参照）、展示モードの
自動再生・終了検知が最初から効かない特殊経路だった。動画を全部ローカルに
落とす運用に決めたことで、この特殊経路自体が不要になった。

**追加の効果**: `data.js` に動画を足すときの必須項目が `title` と `file` だけになり、
ドライブ URL から ID を取り出す手順が丸ごと無くなった。詳細は [data.md](data.md)。

## 動画はフォルダに置くだけで反映する（2026-09-10）

`src/videos/<カテゴリid>/` に動画ファイルを置けば、球体の星・カテゴリページ・
自動再生まで自動で反映される形にしました。`src/js/data.js` を手で編集する必要はありません。

### なぜサーバー側で走査するのか

**ブラウザだけではフォルダの中身を読めません。**

- ブラウザにディレクトリ一覧の API が無い
- `file://` では `fetch` が使えない（`structure.test.js` が `src/` の JS への
  `fetch` / `XMLHttpRequest` を禁止しているのはこのため）

そこで `serve.py` が配信のたびにフォルダを走査し、`src/js/videos.js` を生成します。
ページ側は素の `<script src="js/videos.js">` で読むだけなので、`fetch` は増えません。

```
src/videos/ai/研究テーマ（山田）.mp4
        ↓  serve.py が走査
src/js/videos.js  window.HIDD_VIDEO_FILES = { "ai": ["研究テーマ（山田）.mp4"] }
        ↓  data.js の applyVideoFiles が読む
categories[].videos          ← ここから先は今までと同じ（星の生成も自動）
```

**リクエストのたびに作り直すので、サーバーの再起動は要りません。**
動画を足してブラウザを再読み込みするだけで反映されます。
生成した内容はディスクにも書くので、`file://` で開いたときは最後の内容が使われます。

### ファイル名の解釈は JS 側（`parseVideoName`）に置いた

Python 側でパースすると、このリポジトリのテスト（Node 標準のテストランナー）から
検証できなくなります。`serve.py` はファイル名を並べるだけに留め、
タイトルと発表者の切り出しは `data.js` に持たせました。

配布された動画のファイル名は表記が揺れていたので、**リネーム不要でそのまま置ける**
ことを優先しています。実際に配布された 18 本すべてを `data.test.js` の
ケースに入れてあります。

| 揺れ | 例 |
|---|---|
| 半角・全角の括弧 | `…研究(中島).mp4` / `…研究（山田）.mp4` |
| 開きと閉じの食い違い | `…研究開発(佐藤）.mp4` |
| アンダースコア区切り | `…実践研究_小嶋翼.mp4` |
| 重複ダウンロードの連番 | `…研究(佐々木、岡田) (1).mp4` |
| 発表者なし | `球体型ロボのVR遠隔操作に関する実践研究.mp4` |

`【２期】` のような角括弧はタイトルの一部として残します。
先頭の `01_` は並び順のための番号として扱い、表示からは外します
（これを入れないと `_` 区切りの発表者と衝突し、`01_タイトル.mp4` が
「タイトル」という発表者だと解釈されてしまう。テストで気づいた）。

### 空のフォルダは data.js の記述にフォールバックする

まだ動画を入れていないカテゴリは、`data.js` に書かれた確認用の記述
（`videos/sample/` の色パターン）がそのまま使われます。
実物を入れる前でもページが壊れないようにするためです。

## 球体画面の再生カードを表示領域いっぱいにする（2026-09-10）

### ポップアップは 2 か所にある（間違えた）

「球体の画面のポップアップが小さい」という指摘に対して、
`category.html` の `.modal` をずっと直していた。**直すべきは `index.html` の `.grow` だった。**

| 画面 | 実装 | 元のサイズ |
|---|---|---|
| 球体（`index.html`） | `.grow__card` | `width: min(430px, 88%)` |
| カテゴリ一覧（`category.html`） | `.modal__panel` | 別物 |

指摘に「球体の画面の」と書いてあったのに確認しなかった。**どのページの話かは最初に確定させること。**

### .sphere-wrap に閉じ込められていた

`.grow` は `position: absolute` で、親の `.sphere-wrap`（`max-width: 1180px` / `overflow: hidden`）の
内側に収まっていた。`position: fixed` にして表示領域まで広げた。
祖先に `transform` / `filter` が無いことは確認済み（あると `fixed` の基準がそこになる）。

カテゴリ名・タイトル・発表者は `position: absolute` で動画の上に重ねる。
行として置くと、その分だけ確実に動画が縮むため。
重ねた文字は `pointer-events: none` にして、動画のシークや再生を邪魔しないようにしている
（× ボタンだけ `pointer-events: auto`）。

1224x666 の画面で、動画の絵は **402x226 → 1184x666（面積 8.7 倍）**。

### 16:9 の動画の大きさは「幅」ではなく「高さ」で決まる

調査の途中、`category.html` 側でも同じ勘違いをして幅の上限を広げたが、逆効果だった。
16:9 の動画は幅を広げるほど縦に伸びる。縦が足りなければ、はみ出した分が
スクロール送りになって見切れる（`overflow: auto` のパネルの場合）。
**枠・余白・見出しの行に使った場所は、そのぶん確実に動画から引かれる。**

**寸法に `vw` を使わないこと。** `vw` はモーダル自身の `padding` もスクロールバーの幅も
勘定に入れない。`98vw` と書いて、狭い画面（570px 幅）で右に 0.59px はみ出したことがある。
`inset: 0` の固定配置なら `100%` がそのまま表示領域になる。

※ `category.html` 側にも同じ見切れがあるが、今回は球体画面だけを直した（依頼の範囲外のため）。

### 開くタイマーと閉じるタイマーが競合していた（5 回目）

Esc で閉じない不具合を追ったら、`stars.js` に前からあった競合が見つかった。

```
openCard  : grow.hidden = false;  setTimeout(() => add('is-open'), 20)
closeCard : remove('is-open');    setTimeout(() => { if (!has('is-open')) hidden = true }, 320)
```

**閉じる合図が、開く合図より先に走ると壊れる。** `closeCard` が `is-open` を外したあとに、
遅れて発火した `openCard` のタイマーが付け直す。すると 320ms 後の後始末が
「まだ開いている」と判断して `hidden = true` をスキップし、カードが閉じないまま残る。

**タブが非表示だと `setTimeout` は 1 秒以上に間引かれる**ので、これは実際に起きる。
低スペック機でも起きうる。`openCard` のタイマーを控えておき、`closeCard` の先頭で
`clearTimeout` するようにした。

rAF だけでなく **`setTimeout` も遅延する**という点で、これまでの 4 件と同じ穴。
「合図を出したから届いたはず」と考えないこと。

### Esc で閉じられるようにした

`noteActivity()`（操作があったときの集約点）が `phase === 'playing'` なら `closeCard()` を呼ぶ設計で、
Esc は元からここに繋がっていた。閉じなかったのは上の競合が原因なので、**Esc 用の追加処理は要らなかった**。

全画面になって背景クリックで閉じられなくなったため、閉じる手段は × と Esc の 2 つ。

## 無操作の判定に球体の動きも入れる（2026-09-10）

球体を掴んだまま長く引きずっていると、途中で「操作なし」と判定され、
**触っている最中に自動再生が始まっていた。**

### 原因: 進行の計測がイベントの種類に依存していた

無操作の計測は `noteActivity()` が一手に引き受けていて、`pointerdown` / `pointerup` /
ホイール / キーでは呼ばれるが、**`pointermove` からは呼ばれない**。
ドラッグ中は `pointermove` しか来ないので、`pointerdown` で仕掛けた 5 秒のタイマーが
そのまま満了する。手はずっと動いているのに、計測側からは無人に見えていた。

### 直し方: 「動いているか」を状態で見る

計測を始める処理を `armIdle()` に切り出し、**始めてよいかを状態で判断する**ようにした。

- 掴んでいるあいだ（`dragging` / ピンチ 2 点）は始めない。離した時点（`endDrag`）で測り直す
- 手を離したあとの惰性で回っているあいだも操作中とみなし、
  **巡回と同じ速さ（`TOUR_RAD_PER_SEC` = 0.35 rad/s）まで落ちてから** 5 秒を数える

イベントが来たかどうかではなく、球体が動いているかどうかを見るので、
`pointermove` を計測に足す（＝毎フレーム タイマーを張り直す）必要がない。

### 惰性の残り時間は式で解く（rAF に頼らない）

速度は 1 秒あたり `FRICTION` 倍に減る（`v(t) = v0 · FRICTION^t`）ので、
落ち着くまでの時間は `t = log(settle / v0) / log(FRICTION)` で**先に求まる**。
`HIDDGeom.spinSettleMs()` に置いて `test/geometry.test.js` で検証している。

rAF の進み具合を見て「止まったら数え始める」とすると、
**タブ非表示で rAF が止まった瞬間に計測も止まる**（過去に 5 回踏んだ穴と同じ）。
最初に `IDLE_MS + 惰性の残り` を一発の `setTimeout` に載せれば、その穴を踏まない。

最大の勢い（速度の上限 6 rad/s）で弾いた場合、巡回の再開まで約 21 秒
（惰性 16 秒 ＋ 無操作 5 秒）。そのあいだ球体は実際に目に見えて回っている。

### 離したことを取りこぼすと巡回が戻らなくなった

掴んでいるあいだ計測を止める以上、**`pointerup` を逃すと二度と始まらない**。
`pointercapture` が失敗して球体の外で離した場合に備え、`pointerup` / `pointercancel` は
`window` で受けるようにした。

ピンチも同じ穴だった。`endDrag` は `dragging` が false だと即 return するが、
ピンチ中は `dragging` を落としてあるため、指を離しても測り直されない。
ピンチだったときは `noteActivity()` を呼んでから return する。

## カテゴリの導線を左上のメニューに移す（2026-09-10）

球体の下に並べていたカテゴリの一覧をやめ、**左上にロゴとメニューボタン**を置いた。
ボタンを押すとカテゴリの一覧が開き、そこから各ページへ移動する。

球体そのものがカテゴリを選ぶ操作なので、下の一覧は同じ導線の重複だった。
画面の下端が空くぶん、球体を大きく見せられる。

### 一覧の要素は消さずに残す

`.fallback-nav` は **WebGL が使えない環境では唯一の導線**（`.no-webgl` で球体を隠し、
一覧をカード表示に切り替えている）。消さずに `display: none` で伏せ、
`.no-webgl .fallback-nav` で戻している。`structure.test.js` が両方を検査する。

項目の文言は `data.js` の `categories` から作る。メニュー側にも書き写すと、
カテゴリを増減したときに必ず片方が古くなる。

### ロゴの黒は PNG 側で透過にした（`img/HIDD-mark.png`）

もらった `img/HIDD.png` は**黒地に白抜き**。暗い背景（`--bg` = #06070d）の上に置くと、
黒が微妙に濃くて四角い縁が出る。

`mix-blend-mode: screen` では消せなかった。**合成はスタッキングコンテキストの内側で閉じる**ため、
`position: fixed` ＋ `z-index` を持つ `.site-head` の中では、ページの背景まで届かない。
`mask-mode: luminance` は対応していないブラウザで白い四角になる（失敗の仕方が悪い）。

そこで、元画像から**輝度をそのまま不透明度にした PNG** を作って置いた
（白抜き部分＝輝度が高い＝不透明、黒地＝輝度 0＝透明。黒で合成済みの絵なので、
色は白に置き換えてよい）。透明な余白も落として 1184×240 にしてある。
元の `HIDD.png` は残してあるので、作り直せる。

### 開いているあいだは「操作中」にする

無人展示なので、メニューを見ている最中に自動再生が始まると邪魔になる。
`armIdle()`（`stars.js`）が `HIDDMenu.isOpen()` を見て、開いているあいだは無操作を数えない。

ただし**開いたまま放置されると展示が止まる**ので、20 秒のあいだ何も触られなければ
メニュー自身が閉じ、そこから計測を再開させる（`menu.js` の `MENU_IDLE_MS`）。

開閉は class の付け外しだけにしてある。`hidden` 属性をタイマーで外す作り方は、
遅延したときに開いたまま／閉じたままになる（このリポジトリで 5 回踏んでいる穴）。
表示・非表示は `visibility` で切り替え、transition と競合させない。

### 全画面の再生カードは body 直下に置く

左上の見出しを足したら、**自動再生中の動画の上にロゴが重なった。**

`.grow`（再生カード）は `z-index: 500`、`.site-head` は `6`。数字だけ見れば負けないが、
カードは `.stage`（`z-index: 1`）の中にあった。**重なり順はスタッキングコンテキストの内側で閉じる**ので、
根っこで比べられるのは `.stage`（1）と `.site-head`（6）であり、中の 500 は関係ない。

`z-index` をいくら上げても直らない。カードの要素そのものを `body` 直下へ出した。
`position: fixed; inset: 0` なので見た目は変わらず、`.sphere-wrap` の `is-playing`（球体を暗くする）も
ラップ自身に付けているため影響しない。`structure.test.js` が `<main class="stage">` の外にあることを検査する。

同じ理由で、**新しく最前面に出したい要素を `.stage` の中に足さないこと。**

### 自動的に閉じるときは noteActivity を呼ばない

メニューは放置されると 20 秒で自分を閉じる。ここで `noteActivity()` を呼ぶと
**再生中の動画まで閉じてしまう**（`noteActivity` は「人が操作を取り戻した」の合図で、
`phase === 'playing'` ならカードを閉じる仕様）。メニューを開いたまま星を押すと実際に起きた。

人の操作（クリック・Esc・外側クリック）は `noteActivity()`、
タイマーによる自動的な閉じは `HIDDSphere.armIdle()` だけを呼び、計測の再開に留めている。
`armIdle()` は `phase !== 'idle'` と二重張りを弾くので、再生中に呼ばれても何もしない。
