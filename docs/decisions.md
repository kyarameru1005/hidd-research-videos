# 設計判断と落とし穴の記録

同じ検討を繰り返さないための記録です。要件の原文は [requirements.md](requirements.md) を参照。

## 技術選定

### ビルド工程を持たない

ページ数が少なく（本番 2 枚）、サーバー機能も不要なため、素の HTML / CSS / JS にしました。
`src/index.html` をダブルクリックするだけで動きます。

### Three.js は UMD 版 (r149) を同梱

`file://` で開く要件があるため、`type="module"` + `import` は使えません
（ローカルファイルの ES module は origin `null` で CORS ブロックされる）。
Three.js は r150 以降 UMD ビルドを廃止しているので、**UMD 最終版の r149** を
`src/vendor/three.min.js` に置いています。CDN 参照にしないのはオフラインでも動かすためです。

### 球体テクスチャは画像を使わず JavaScript で生成

Chrome は `file://` のページから読んだ画像を「別オリジン」扱いにするため、
**WebGL テクスチャに転送できません**。`src/js/texture-lab.js` が Canvas 2D で
描いたものを `CanvasTexture` にしています。追加のダウンロードも発生しません。

現在は「カテゴリ色の 4 分割グロー」を採用（`demo/texture.html` の案 2）。
別案に変えたい場合は `src/js/stars.js` の `HIDDTexture.materials.quad()` を
`dots` / `circuit` / `rim` / `nebula` / `globe` に差し替えます。

### カテゴリ名は 3D テキストではなく HTML 要素

球面にテキストを貼ると日本語が歪む・重い・にじむため、球面上のアンカーを
毎フレーム `Vector3.project(camera)` で 2D 座標に変換し、通常の HTML 要素を動かしています。
クリック・ホバー・フォーカスが標準機能で済み、支援技術からも読めます。

## 低スペック PC への配慮

- **静止したら描画ループを止める。** 回転中・アニメーション中だけ `requestAnimationFrame` を回す
- タブが見えていないあいだは描画しない
- 解像度は `devicePixelRatio` 1.5 までに制限
- ライトオブジェクトもポストプロセスも使わず、陰影とリムライトは 1 パスの軽いシェーダで処理
- テクスチャは起動時に 1 枚（512×256）生成するだけ

## 踏んだ落とし穴

### requestAnimationFrame はタブが非表示だと完全に止まる

**重要な処理を rAF の完了に紐づけてはいけません。** 実際に 2 回踏みました。

1. カテゴリをクリック → 回転アニメ完了 → ページ遷移、としていたら、背景タブでは永久に遷移しなかった
2. 星をクリック → 回転アニメ完了 → カードを開く、で同じことが起きた

どちらも **`setTimeout` に切り離して**解決しています。アニメーションは見た目だけの責務にします。

### scroll イベントも描画フレームに紐づいている（3 回目）

フィルムストリップの送りボタンで同じ穴を踏みかけました。
`scrollBy({ behavior: 'smooth' })` はタブが非表示だと**まったく進まず**、
`scroll` イベントも飛んできません。ボタンの有効・無効を `scroll` イベントだけで
更新していたため、「←」が無効のまま押せなくなる状態でした。

`src/js/category.js` の `scrollBySteps()` は、スクロールを出したあと
`setTimeout(updateNav, 60)` と `setTimeout(updateNav, 500)` でも状態を直しています。
`scroll` イベントの購読は指やトラックパッドでの操作用に残してあります。

同じ判断基準です: **フレームが来ないと止まるものに、進行を任せない。**

### デモから本番へ移すときに同じ穴を持ち込んだ（4 回目）

`demo/js/stars.js` から `src/js/stars.js`（本番）へ移すときに、
カードを開く class を `requestAnimationFrame` の中で足すコードをそのまま持ち込んでいました。
**再生は始まっているのに、カードが `opacity: 0` のまま見えない**状態になります。
`setTimeout(..., 20)` に変え、`structure.test.js` で検出するようにしました。

### JS が毎フレーム書く CSS プロパティに transition を掛けない

`.label--brand` に `transition: opacity .8s` が残っていたため、JS が毎フレーム書く
opacity に追従できず、**HIDD の文字が薄いまま止まって見えました**。
JS で制御する値には transition を掛けないこと。

### ノイズのハッシュは論理シフト（`>>>`）を使う

算術シフト（`>>`）だと負の座標で符号ビットが伝播し、XOR 後の最上位ビットが常に 0 になって
**値域が 0〜0.5 に潰れます**（平均 0.25）。星雲・地球儀テクスチャの模様が出なかった原因です。

### ジオデシック球のワイヤーは球面より外側に置く

多面体の辺は弦なので、球と同じ半径だと辺の中間が内側に沈んで隠れます。
detail 2 で約 1.5% のたわみがあるため、半径 1.03 程度に置く必要があります。
（現在は本番からワイヤーを削除済み）

### Points のマーカーは輪郭に隠れる

カメラ距離 3.6 では半径 1.04 以上でないと球の輪郭より外に出ません。
`THREE.Points` は既定で四角く描かれるので、丸くするには放射グラデーションのスプライトが要ります。

### Python の `http.server` は Range 非対応

206 ではなく 200 を返すため、**動画のシークと再生位置の復元が効きません**。
Range に対応した `serve.py` を用意しました。

### Google ドライブの埋め込みは JS から操作できない

別オリジンの iframe なので、再生位置の取得・設定、再生の開始、終了の検知が
**すべて不可能**です（ブラウザのセキュリティ仕様で、ドライブ固有の制限ではありません）。
放置時の自動再生を実現するには、動画をローカルに置くか YouTube 限定公開に移す必要があります。

## テスト

`node --test test/*.test.js`。Node 標準のテストランナーのみで、npm は使いません
（ビルド工程を持たない方針と揃えるため）。

ブラウザ無しで検証できるものに絞っています。

| ファイル | 見ているもの |
|---|---|
| `data.test.js` | `src/js/data.js` の整合性（id 重複、色重複、必須項目、URL 組み立て） |
| `geometry.test.js` | 回転の計算。**任意の向きが正面に来ること**と pitch が可動域に収まること |
| `structure.test.js` | 構成の決まりごと。参照切れ、`type="module"`、外部依存、`fetch`、過去の不具合の再発 |

`src/js/geometry.js` は、この検証のために球体のスクリプトと `demo/js/stars.js` から
共通の計算を切り出したものです（同じ関数が 2 か所に重複していた）。
**DOM に触れないロジックはここに置けばテストできます。**

描画そのもの（Three.js の出力、CSS の見え方、動画の再生）は自動テストの対象外です。
ブラウザで確認してください。

## 動画一覧ページの UI

### 案 5「フィルムストリップ」を採用（2026-09-09）

`demo/category-ui.html` の 6 案から選定。カード型のグリッドは
「AI っぽい」との指摘があり、横スクロールの縦長パネルに変更しました。
本番は `src/category.html` / `src/css/category.css` / `src/js/category.js`。

デモの `.ui5__*` をそのまま持ち込まず、本番では `.strip__*`（枠）と
`.film__*`（1 本ぶんのコマ）に名前を付け直しています。
デモ側の 6 案は比較の記録としてそのまま残しました。

**デモと本番で違うところ**

| | デモ (`ui5`) | 本番 |
|---|---|---|
| コマの要素 | `div` | `button`（Tab でたどれる・Enter で再生） |
| 送り操作 | 横スクロールのみ | 見出し行の ← → ボタンと矢印キーも |
| 動画リンク未設定 | 考慮なし | コマを `disabled` にして「動画リンク未設定」と出す |

**送りボタンをパネルに重ねなかった理由**
最初はよくあるカルーセルのように左右端へ重ねて置きましたが、
先頭と末尾のコマの内容を隠してしまったので、見出し行へ移しました。
狭い画面でも位置が変わらず、出し分けの条件分岐も要りません。

**カード型の CSS は `demo/css/category-ui.css` へ移した**
`.video-grid` / `.video-card` は本番から消えましたが、デモの「旧実装（参考）」が
`../src/css/category.css` を読んで使っていたため、`.uid-current` 配下に写して保持しています。

## 無人展示で音を出す

### 1 回の操作で解除、以降は無人でも音つき（2026-09-09）

`demo/js/stars.js` に追加し、本番採用にともなって `src/js/stars.js` にもそのまま
持ち込みました。ブラウザは音ありの自動再生を、その場での操作なしには許可しません。
ただし一度でもクリック・タップ・キー操作があれば、そのタブでは**以降ずっと
解除されたまま**になります（`navigator.userActivation.hasBeenActive`）。

これを利用し、`document` に 1 回限りのリスナーを追加しました
（`unlockSound()`、`pointerdown` / `keydown` を各 `{ once: true }` で購読）。
展示を始めるときに画面へ 1 回触れれば、それ以降は無人でも音つきで流れ続けます。
デモには音の設定パネル（`音: あり`）もあり、そこを直接押しても解除されます
（本番の `index.html` に設定パネルはありません）。

**それでも再生がブロックされた場合の保険**
`openCard()` で `v.play()` が rejected したら、まずミュートで再試行するようにしました
（`src/js/category.js` ではなく `src/js/stars.js` / `demo/js/stars.js` 側）。
無人展示で「音ありのまま一切再生できず、12 秒ごとに全部スキップされ続ける」
という壊れ方を避けるためです。

**それでも「PC の電源が入ったら誰も触らず即座に音」が要る場合**
JS だけでは解決できません（ブラウザの仕様のため）。`docs/operations.md` に
`--autoplay-policy=no-user-gesture-required` での Chrome 起動方法を記載しました。
展示専用の Chrome プロファイルを分けることを推奨しています。

## トップページ

### 星のインタフェースを採用（2026-09-09）

`demo/stars.html` を本番の `src/index.html` に取り込みました。
**1 等星＝カテゴリ、周りの小星＝動画 1 本ずつ**の階層構造です。

展示の設定は固定値にしました（デモにあった設定パネルは本番には持ち込んでいません）。

| 項目 | 値 | 場所 |
|---|---|---|
| 放置してから回り出すまで | 5 秒 | `IDLE_MS` |
| 回り出してから再生まで | 5 秒 | `PLAY_MS` |
| 星座線 | あり（常時） | — |
| 音 | あり（最初から音ありで試す） | — |

**1 等星を押したときの動作は A（球体上で選択）にしました。**
球体だけで動画選択まで完結しますが、カテゴリページ（`category.html`）も残しています。
カテゴリを選択すると状態表示に一覧ページへのリンクが出るほか、
画面下部のカテゴリ一覧からいつでも移動できます。
一覧のほうが本数が多いときに見渡しやすく、キーボードと支援技術の導線にもなるためです。

**`src/js/sphere.js` は削除しました。** `index.html` が読まなくなり、
使われないコードが本番に残る状態を避けるためです（履歴には残っています）。
テストの参照先も `src/js/stars.js` へ移しました。

### 動画はローカルファイルを使う

自動再生には `src/js/data.js` の `file`（ローカル動画）が要ります。
ドライブ埋め込みは別オリジンの iframe なので、再生開始も終了検知もできません
（`file` が無い動画は埋め込みを出したうえで 20 秒で次へ送ります）。
今は動作確認用の `videos/sample/` を指しているので、実物を置いたら差し替えてください。
